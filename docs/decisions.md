## Decision log

- **D11 clarified.** "No big files" is enforced as `max-lines` ~300 (raised from 150) so a shadcn
  primitive or a component with its tightly-coupled sub-parts can stay one unit; anything past ~300
  lines, or a genuinely unrelated function bundled into an existing file, must be split. The rule
  lives at the top of [`AGENTS.md`](../AGENTS.md) and in `eslint.config.mjs`.
- **D12 updated & D16 added (School Achievements Standalone Route & Platform Owner Exclusivity).**
  Moved from `/calendar` tabs into a dedicated standalone route (`/achievements`). Access is strictly gated
  to the Platform Owner (`roles.key === 'owner'`). Completely hidden from navigation, mobile drawers,
  dashboard widgets, quick actions, and statistics grids for all non-owner roles (including school managers
  and administrators), serving as an isolated premium add-on feature.
- **D13 added (Platform Owner Account Protection).** School-level administrators must not possess the ability to alter or view global Platform Owner credentials or profiles. Server actions (`assertCanManageUser`) and user mapping queries strictly enforce tenant boundaries and hide owner records from tenant admin views.
- **D14 added (Reports Scoping).** Executive reports and compliance dashboards are segregated from departmental accounts. Department Heads view and respond only to circulars and maintenance relevant to their unit, while full-school compliance analytics remain reserved for executive leadership (`owner`, `school_admin`).
- **D15 added (Unified Calendar & Personalized Deadlines).** Rather than isolating administrative deadlines in circulars, calendar views dynamically aggregate school calendar events with target-scoped circular deadlines (`due_at`, `publish_at`). Interactive detail dialogs (`CalendarItemDetailDialog`) reveal complete event details and circular response instructions without navigation disruptions.
- **D17 added (Reports & Analytics Multi-Criteria Filtering & Sorting).** Added dynamic date sorting (newest/oldest), temporal filters (all time, monthly view, and custom date range picker), and department-based filtering across both Circulars Compliance and Maintenance & SLA tabs.
- **D18 added (App-Wide Accessible Confirmation Dialog - `AppMessageBox`).** All native browser `confirm()` calls were systematically eradicated and replaced with an in-app, theme-aware, fully accessible confirmation modal (`AppMessageBox` powered by a global bridge and `showConfirmBox`). This standardizes UX across deletion actions for departments, locations, users, circulars, achievements, and maintenance requests.
- **D19 added (Maintenance Operator Role Exclusivity).** Maintenance work order assignment strictly enforces that only active users holding the `operator` role (`فني صيانة`) appear in the technician dispatch list. If a school has zero registered technicians, the assignment panel renders a warning alert guiding the administrator to `/settings/users` and disables assignment to prevent mistaken delegation.
- **D20 added (School Operational Calendar & Weekend Policy).** Aligned with the Gulf/Kuwait educational workweek (Sunday through Thursday), Friday and Saturday are configured as official weekly holidays. Calendar event scheduling on Friday or Saturday is rejected on form input change, form submission, and server actions (`assertValidCalendarInput`). Recurring event generation automatically omits weekend dates, and calendar month views prominently highlight Friday and Saturday columns.
- **D21 added (School Profile Structured Sub-Tabs).** Refactored the monolithic School Profile settings form into 6 distinct sub-tabs: School Identity, Leadership, Location & Contact, Academic Year, Vision & Mission, and Operations. Each tab is navigable via URL hash and tab buttons to prevent visual overload while keeping form persistence unified.
- **D22 added (Database Backup & Disaster Recovery Exclusivity).** Added a JSON snapshot export and validated restore interface under `/settings/backup`. Strictly gated to the Platform Owner (`roles.key === 'owner'`). Hidden from sidebar, mobile navigation, and settings tabs for school managers and staff. Server actions (`exportBackupAction`, `restoreBackupAction`) verify ownership before execution. Backup exports scrub owner records to preserve platform isolation.
- **D23 added (Platform Owner Zero-Knowledge Scrub).** Scrubbed all references to "Platform Owner" across tenant-visible screens, role selector dropdowns, staff management tables, and localization files. Regular administrators and teachers operate with zero knowledge of the owner's existence.
- **D24 added (Unified Minimum Password Length).** Unified password length validation across user creation, reset password action, login schema, and HTML input attributes to a consistent minimum of 6 characters, eliminating discrepancies between account provisioning and sign-in gates.
- **D25 added (Neutralized Royal Navy Default Theme).** Renamed the primary default theme from "Al-Nada" to "Royal Navy (Default)" / "كحلي ملكي (افتراضي)" to decouple the design system from specific school names. Configured Royal Navy color tokens at the `:root` level in `globals.css` to ensure zero-flicker default styling across initial loads.
- **D26 added (User Management via Admin Client).** Resolved PostgreSQL RLS 42501 error when school managers delete or toggle staff members. Because disassociating a user sets `school_id: null`, standard RLS policies evaluate `has_permission(..., null)` to false. Authorized manager requests verify tenant permissions first, then execute profile updates via the Supabase admin client.
- **D27 added (Universal In-App PDF.js Viewer).** Replaced all `<iframe>` and external-tab (`target="_blank"`) PDF previews across School Documents, Circular Attachments, and Achievement Attachments with `InAppPdfViewer` (`src/components/pdf/`), powered by `pdfjs-dist` with self-hosted same-origin `worker`, `cmaps`, `standard_fonts`, and `wasm` decoders (`public/pdfjs/`), strict CSP (`worker-src 'self'` and `'wasm-unsafe-eval'`), serialized per-canvas rendering, and split `IntersectionObserver`s for lazy loading and active-page tracking.
- **D27 added (Phone-first adaptive UI).** One codebase, CSS-first adaptive layout below `md` (<768px): compact top bar with back button, a bottom tab bar (Dashboard, Circulars, Calendar, Maintenance, More), a More bottom sheet carrying the existing permission-gated destinations, cards instead of tables, filter and detail content in sheets and tabs, and sticky form action bars. Desktop layout is unchanged. See `docs/mobile-ui.md`.
